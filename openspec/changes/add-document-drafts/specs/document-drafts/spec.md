# Spec Delta

## Purpose

为文档编辑提供当前浏览器内的草稿恢复和离开保护，使用户在刷新、切换文档或取消编辑后能够找回未正式保存的修改，同时明确区分本地草稿与服务端已保存内容，降低误覆盖和重复编辑的风险。

## ADDED Requirements

### Requirement: 本地草稿隔离与保存
系统 SHALL 在编辑 Markdown 或 API 基本信息后自动保存本地草稿，按系统、用户、项目及文档隔离，新建文档按目录和类型隔离。仅保存可编辑字段及基础快照，不保存认证信息。

#### Scenario: 刷新后找回修改
- **WHEN** 用户修改名称或正文并刷新，再次进入同一文档编辑
- **THEN** 系统显示可恢复草稿，不自动修改服务端文档

#### Scenario: 用户或文档不同
- **WHEN** 另一用户或另一项目文档进入编辑
- **THEN** 不显示原用户或原文档的草稿

### Requirement: 明确恢复或丢弃
系统 SHALL 通过项目标准弹窗提供恢复、丢弃和暂不编辑操作，底层编辑内容保持可见；基础内容变化时提示冲突，恢复仅覆盖本地可编辑字段并保留最新服务端元数据。关闭或暂不编辑 SHALL 保留草稿并退出编辑。

#### Scenario: 服务端已变化
- **WHEN** 草稿基础与最新文档内容不同
- **THEN** 提醒服务端已变化，等待用户选择恢复或丢弃，不自动覆盖

#### Scenario: 暂不恢复
- **WHEN** 用户关闭恢复弹窗或选择暂不编辑
- **THEN** 返回文档查看且保留草稿，下次编辑仍可恢复

### Requirement: 低侵入状态提示
系统 SHALL 将普通草稿状态显示在保存按钮附近，用简短文本和悬浮说明替代顶部整行横幅；离开确认 SHALL 使用项目标准确认窗口。

#### Scenario: 自动保存完成
- **WHEN** 本地草稿自动保存完成
- **THEN** 按钮旁显示草稿已保存，悬浮说明尚未正式保存，不增加顶部提示区域

### Requirement: 离开保护
系统 SHALL 在有未正式保存修改时，对切换文档、取消编辑及路由离开提供保留草稿并离开、放弃草稿并离开、继续编辑三项操作；关闭窗口保持当前编辑。刷新和关闭浏览器使用原生提示，并立即保存待写草稿。

#### Scenario: 取消切换
- **WHEN** 用户尝试切换文档并取消离开确认
- **THEN** 原编辑器内容保持不变

#### Scenario: 确认离开
- **WHEN** 用户确认离开
- **THEN** 保留本地草稿并执行切换

#### Scenario: 放弃草稿离开
- **WHEN** 用户选择放弃草稿并离开
- **THEN** 清理当前草稿后执行切换，卸载时不重新生成草稿；清理失败则留在当前编辑状态并提示错误

### Requirement: 成功保存与异常处理
系统 SHALL 仅在正式保存成功后清理对应草稿，失败时保留；本地存储失败时显示明确提示且保持编辑能力。没有修改时不产生草稿或离开提示。

#### Scenario: 保存失败
- **WHEN** 正式保存因网络或服务端错误失败
- **THEN** 当前修改和本地草稿保持可用

#### Scenario: 其他标签页已更新草稿
- **WHEN** 当前页面退出或正式保存完成，但另一标签页写入了更新的草稿
- **THEN** 不清理另一标签页的草稿；没有修改且未持有草稿的页面不执行草稿清理

#### Scenario: 存储不可用
- **WHEN** 浏览器禁止存储或容量不足
- **THEN** 显示草稿未能保存的提示，离开确认提示丢失风险
