# Design

## Context

两个编辑器调用 getById 后维护独立模型，复用 MarkdownDocEditHeader 保存。目录通过 showDocDetails 和 clearAndSetValue 切换；项目页可能被 KeepAlive 缓存。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 统一编辑生命周期、草稿状态和离开检查，防止迟到的加载响应覆盖新文档。

**Non-Goals:** 不自动提交服务器，不实现多人合并、云端草稿或完整 Schema 表单草稿。

## Decisions

- 使用共用 composable 管理两个编辑器的加载、基础快照、500ms 防抖持久化和保存完成；独立纯函数工具负责字段白名单和缓存结构，便于验证。
- 两个编辑器复用 DocEditorLayout 管理恢复弹窗、状态、保存头部和编辑锁定，业务正文通过插槽传入。保存锁覆盖异步校验与请求全程。
- 使用 localStorage 每文档一个键，键包含系统与用户标识；单份上限 1 MiB，草稿有效期 30 天。相较新增 IndexedDB 库更轻量；失败显式展示，不宣称已保存。
- 草稿保存基础可编辑字段和版本，恢复只合并白名单，不恢复旧版本、权限、项目树等元数据。草稿存在时使用 common-window 提供恢复、丢弃和暂不编辑；关闭或暂不编辑保留草稿并退出编辑。底层编辑内容保持可见但暂时不可操作，避免空白页面与未选择时覆盖草稿。
- 恢复与离开选择复用基于 common-window 的 DocDraftWindow，离开按钮精简为“保留草稿”“放弃草稿”“继续编辑”，正文说明前两项会离开编辑。关闭等同继续编辑；放弃先清理并还原编辑基线，防止卸载时重新生成草稿；清理或保留失败不离开。普通草稿状态在保存/取消按钮旁简短显示，详细说明通过 Tooltip 呈现，不再占据编辑区顶部整行。加载失败保留独立重试入口。
- 项目页提供当前编辑器离开检查，目录切换在修改导航记录前等待检查；共用头部取消也使用检查。路由离开/参数变化、卸载和页面隐藏刷新保存；失活时解除浏览器提示。
- 同项目 docId 路由变化通过路由守卫后，目录定位复用已确认结果；普通目录点击、搜索选择、初始化与项目刷新保留原检查，避免路由切换连续弹两次离开窗口。
- 保存过程中禁用编辑区域，避免成功响应清理请求发出后新增的修改。加载用序列号忽略过期响应。

## Risks / Trade-offs

- 本地浏览器草稿不是备份 → 界面明确“本地”，关闭隐私模式或清理浏览器数据仍会丢失。
- 多标签页同时编辑同一文档可能最后写入覆盖 → 本期保持单份最新草稿，不承诺多标签合并。
- 未修改页面或较早保存请求可能清理其他标签页新草稿 → 清理前比对本编辑器最后读取/写入的记录，未持有草稿时不清理。
- 加载过程中切换账号 → 请求前固定用户 ID 与项目标识，返回时核验身份，不使用用户名作身份后备键。
- 存储受限 → 保持内存内容、展示失败提示并阻止无提示离开。
- 浏览器原生关闭提示受浏览器交互策略限制 → 防抖和隐藏时保存共同降低丢失风险。

## Migration Plan

仅前端部署，无数据库迁移；回退代码不影响正式文档，草稿带独立前缀和格式版本。
