## Manual regression

以下为交付的人工回归步骤，尚未在真实浏览器执行。本轮尝试读取当前 Chromium 窗口，两次均遇到窗口归属不匹配错误，未能完成视觉实测：

1. 修改 Markdown 名称和正文，检查保存按钮旁的简短状态及悬浮说明；切换目录时选“继续编辑”，检查内容和当前节点不变。再选“保留草稿并离开”，重新编辑原文档，在标准恢复弹窗中恢复。检查底层编辑区保持可见，关闭或暂不编辑应退出编辑并保留草稿。
2. 修改 API 方法、URL、状态、锁定、废弃标记、Operation ID 和描述；刷新后重新编辑并恢复，检查字段完整。
3. 同一目录新建 Markdown，输入后离开；再次新建同类型文档，检查恢复提示。不同目录或类型不应显示该草稿。
4. 检查离开窗口的保留、放弃、继续编辑三项选择；放弃后重新编辑不应出现草稿。修改后取消编辑、浏览器后退、跳转项目和刷新，检查离开保护；无修改时不应提示。
5. 留下草稿后由另一会话修改服务端文档，再进入编辑；检查变化提示，恢复后核对内容，再正式保存。丢弃草稿应保留最新服务端内容。
6. 正式保存成功后再次进入不应出现草稿；保存失败时应保留编辑与草稿。保存期间不能再次保存或切换文档。
7. 禁用浏览器存储或使用超出 1 MiB 的内容，检查明确失败提示和离开时丢失风险提示。
8. 切换用户，确认草稿不可串用；检查深浅主题、英文界面和移动端目录抽屉。
9. 编辑中通过同项目带 docId 的路由切换文档，选择保留后应只确认一次；普通目录点击与高级搜索切换仍需确认，取消时保持原编辑内容。此项已核查路由守卫与目录定位调用链，仍待浏览器端实测。

## Scope

草稿仅存在于当前浏览器，30 天有效，单份最多 1 MiB。独立 Schema 编辑器和调试参数不在本期范围。多标签页同时编辑同一文档不做草稿合并；清理前会比对本编辑器持有的记录，避免删除其他标签页后写入的草稿。功能与 OpenSpec 初始化分开提交；OpenSpec 变更未归档，便于继续审阅。
