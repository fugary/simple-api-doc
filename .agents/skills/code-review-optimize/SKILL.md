# 代码 Review 与精简优化指南 (Code Review & Optimization)

当需要对本次修改或新增的代码进行审查、精简与优化时，请遵循以下规范与步骤：

## 核心要求
1. **深度去重与公共逻辑抽取**：
   - **跨类与跨模块排查**：严格审查本次改动是否在多个类/文件之间复制粘贴了相同或相似的代码逻辑（例如相同的配置 `@Value` 注入、路径处理方法、数据转换与校验逻辑等）。
   - **强制提炼**：发现任何重复逻辑，必须将其强制抽取到公共 Service、Utils、Helper 或常量类中，坚决杜绝代码复制。
   - 检查前端重复的内联样式、冗余逻辑或模板结构，提炼为组件、Hooks、公共函数或全局 CSS 类。

2. **路径与标识符命名安全规范**：
   - 严禁使用可能包含中文、空格或特殊字符的展示字段（如 `projectName`、`title`、`docName`）直接作为物理文件路径、目录名或唯一关联键。
   - 涉及物理路径、目录隔离、缓存键或全局唯一标识时，必须强制优先使用标准的纯 ASCII 标识字段（如 `projectCode`、`repo`、`code`、`id`、`slug`）。

3. **控制变动范围**：
   - 仔细核对 `git diff` / 修改历史，移除不必要的代码侵入和与功能无关的改动。
   - 避免过度重构现有稳定代码，保持高内聚低耦合。

4. **代码优雅与可读性**：
   - 变量与函数命名需清晰明确、符合上下文语义。
   - 优先使用项目已有的公共组件（如 `common-icon`、`common-table`、`common-form` 等）与工具函数。

5. **规范与校验**：
   - 后端修改：确保符合 JDK 11 语法特性，运行全量 Maven 单元测试并通过。
   - 前端修改（Vue / JS 等）：**必须运行 ESLint 校验并通过（0 errors）**方可继续。
   - 遵守项目提交约束：**严禁自动 commit**，修改需通过 git 暂存或保留在工作区供用户确认。
